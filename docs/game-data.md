### 机制结论

`input_type` 决定发射机制，直接影响引擎的发间间隔计算：

**`UP` 型（绝大多数 SR/RL）**：按下蓄力、松手触发。每次发射需重新按下（前摇）→ 蓄力 → 松手后恢复（后摇）。
- 发间 = `foreswingTicks + effectiveCharge + backswingTicks`
- `maintain_fire_stance > 0` 时后摇用该值覆盖 `spot_last_delay`

**`DOWN_Charge` 型（Liberalio 唯一 SR；少数 RL）**：持续按住不松手，满蓄自动连续射击。始终保持瞄准，发间无前摇/后摇。
- 发间 = `max(effectiveCharge, round(3600 / rate_of_fire))` —— RPM 是发间下限；蓄速把蓄力压至近零时（如 Cinderella S1 P2 +100%）射速封顶在 RPM（Cinderella 180 RPM → 20t）。Liberalio 200 RPM → 18t 远低于其 86t 蓄力，不构成约束
- 第 1 发仍含前摇（初次对准）：`foreswingTicks + chargeTimeTicks`
- 换弹后重置**无前摇**（持续按住、无需重新瞄准）：`reloadEndTick + chargeTimeTicks`（UP 型则含前摇）
- 射后触发器推入的蓄速 buff（FULL_CHARGE → Cinderella S1 P2）立即作用于下一次蓄力（引擎在触发器执行后重排 chargeTick）

**`DOWN` 型（Pascal）**：`charge_time = 0`，按下即发，由 `rate_of_fire` RPM 累加器控制节奏。

## 攻速实测记录

> 数据来源说明：Helm / Scarlet:BS 来自**模式1**；Liberalio 来自**模式2**。
> 判据：SBS 33.3s/45发要求第一 HIDDEN ≥33.3s，只有模式1(33.5s)符合；模式2(29.5s)第一阶段仅40发。
> Helm 180s=121发仅与模式1+修复(121)吻合，模式2+修复预测118，不符。

### Helm（SR，UP 型，模式1）

**实测：29.5s 内攻击 21 次，期间无换弹；180s 攻击 121 次，期间无被动换弹（弹匣耗尽）**

- charge_time = 100 cs → chargeTimeTicks = 60t；maintain = 0 → backswingTicks = 12t
- 第 1 发：12 + 60 = **72 ticks = 1.200s**
- 发间：12 + 60 + 12 = **84 ticks = 1.400s/发**
- 29.5s 窗口验证：第 21 发 = 72 + 20×84 = **1752t = 29.20s** ✓（第 22 发 30.60s，21 发在窗口内）
- 180s（模式1，4次HIDDEN）：修复前 **125 发** → 修复后（完整发间重置 84t）**121 发** ✓
- 模式2 对比：完整发间重置预测 **118 发**，与实测 121 不符 → 确认为模式1数据

### Scarlet: Black Shadow（RL，UP 型，模式1）

**实测：33.3s 内攻击 45 次，期间无换弹；180s 攻击 233 次，期间无被动换弹（弹匣耗尽）**

- charge_time = 30 cs → chargeTimeTicks = 18t；maintain = 23 cs → backswingTicks = 14t
- 第 1 发：12 + 18 = **30 ticks = 0.500s**
- 发间：12 + 18 + 14 = **44 ticks = 0.733s/发**
- 33.3s 窗口验证：第 45 发 = 30 + 44×44 = **1966t = 32.77s** ✓；第 46 发 = 2010t = HIDDEN 起始
- 模式2 不可能：HIDDEN 在 1770t(29.5s)，第一阶段仅 40 发（第 41 发 1790t 在 HIDDEN 内）
- 180s（模式1，4次HIDDEN）：修复前 **236 发** → 修复后（完整发间重置 44t）**232 发**（实测 233，差 ±1）

### Liberalio（SR，DOWN_Charge 型，模式2）

**实测：stage target，OL 蓄力速度 4.84%，26.2s 内攻击 18 次，期间无换弹**
**实测：stage target，OL 蓄力速度 4.84%，180s 完整战斗攻击 106 次（含 Little Mermaid 补弹，多次换弹）**

## 爆裂槽充能机制（2026-06-25 实测）

测试环境：联盟射击场-BIGARMS，G（爆裂槽总量）固定 **1,000,000**。

### 基准：Privaty 每发充能 = 4000

- 单独 Privaty（AR，60 弹匣）充满共攻击 4×60+6 = 246 发。
- 246 × 4000 = 984,000；剩余 16,000 来自 4 次换弹触发的 **Privaty S2P1 充能效果**（每次 = 1 发普通攻击 = 4000）。
- 984,000 + 4×4000 = **1,000,000** ✓ → Privaty 每发 = 4000，S2P1 带充能。

  对照：线性半径 + 均匀落点（旧模型形式）34.5、线性 + 高斯 29.6、透视 + 均匀 25.4。
- 装备 / 魔方 / 技能命中率效果相同；三种武器（SMG 110 / AR 75 / SG 250）共用同一 c。

### Minimum Effective Range 机制（由上述实测反推）

```
有效下界 = bonusrange_min × (1 − ΣMinimum Effective Range%)      // SR: bonusrange_min = 45
```

各百分比按 45 设计：Spy Lens 每层 4.44% = 2/45（缩 2 格）、爆裂 55.56% = 25/45（缩 25 格）、10 层 + 爆裂 = 99.96%（下界归零）。

| 状态 | Σ% | 下界 |
|------|----|------|
| 8 层 | 35.52 | 29.0 |
| 9 层 | 39.96 | 27.0 |
| 10 层 | 44.4 | 25.0 |
| 仅爆裂 | 55.56 | 20.0 |
| 10 层 + 爆裂 | 99.96 | ≈0 |

- 时序：第 10 枪同时触发了满层的 S2P2（穿透 + ATK%），但 S2P2 未作用于第 10 枪 → 叠层与满层激活都发生在本发伤害**之后**（与引擎 FULL_CHARGE 射后触发一致）。因此第 10 枪的距离判定用前 9 层（下界 27.0），第 9 枪用 8 层（下界 29.0）。
- 由此 P1 距离：5 号位 ∈ [27, 29)，1 号位 ∈ [29, 31)（第 9 枪判定用 8 层，下界 29.0；第 8 枪用 7 层，下界 31.0）；P2 距离 ∈ [20, 25)。模拟器敌人配置取 P1=30（与核心命中率模型的锚定点一致，落在 1 号位区间内，与 5 号位区间仅差 1–3 格）、P2=20。
- 结论：「Minimum Effective Range ▲ X%」按 bonusrange_min（SR 为 45）等比缩减下界，100% 对应 45 格全部缩减。模拟实现（`src/data/skills/315.js`）按此公式，无需按站位修正。
- 已排除：按 0–100 全刻度减法（10 层下界 0.6，P2 必触发，矛盾）；除法 45/(1+Σ%)（仅爆裂下界 28.9，P2 不可触发，矛盾）。

## Max HP 变化与当前 HP（基础机制，2026-10-12 确认）

- Max HP ▲ 只提升上限，**不按比例保持当前 HP**：满 HP 时获得 Max HP ▲ 会变为不满 HP。与技能描述是否写「without restoring HP」无关。
- Max HP 效果到期 / 扣减时同理：当前 HP 只在高于新上限时截断，否则不变。

## Flora（SSR 珍藏品）S2 触发与开战结算顺序（2026-10-12 实测）

### S2 P2 满 HP 检查（规则确认）

- 进入战斗时检查一次；此后**只在两侧相邻友军的当前 HP 发生变化时**检查。
- 相邻友军始终满 HP 时，即使受到治疗（HP 不变）也不会触发 S2 P2。

### Flora + Scarlet + Trina 站位实测

前提：三人均为电击代码；Scarlet 为 AR、Flora 为 MG、Trina 为 RL → Trina S2 P1「电击步枪队友 Max HP ▲（不回复 HP）」只作用于 Scarlet，
使 Scarlet 当前 HP 不变、HP 比例降到 90% 以下。

| 场景 | 站位（左 → 右） | Flora 相邻 | 开战 S2 P2 | S2 P1 / P3 |
|------|----------------|-----------|-----------|-----------|
| 1 | Flora, Scarlet, Trina | Scarlet | ✔ 触发 | ✔ 稍后（≤0.1s）触发 |
| 2 | Scarlet, Flora, Trina | Scarlet、Trina | ✔ 触发 | ✔ 同上 |
| 3 | Scarlet, Flora, 空位, Trina | Scarlet、空位 | ✔ 触发 | ✔ 同上 |
| 4 | Trina, Flora, Scarlet | Trina、Scarlet | ✔ 触发 | ✔ 同上 |
| 5 | Trina, 空位, Flora, Scarlet | 空位、Scarlet | ✘ 未触发 | ✔ 触发（有无延迟未确认） |
| 6 | Trina, Scarlet, Flora | Scarlet | ✘ 未触发 | ✔ 触发（有无延迟未确认） |

### 推断结论

1. **同一时机的技能按站位从左到右结算。** 场景 1、3（Flora 在 Trina 左）与场景 5、6（Trina 在左）中，Flora 的相邻满 HP 候选都只有 Scarlet，
   结果只取决于二人左右位置：Flora 在左 → 先检查（Scarlet 仍满 HP）→ P2 触发；Trina 在左 → Scarlet 先被加 Max HP → P2 不触发。
   角色编号（411 / 412）在各场景中不变，排除按编号或技能顺序结算。场景 2、4 有始终满 HP 的邻居 Trina，必然触发，不提供顺序信息。
2. **空位占据位置，相邻判定不跳过空位。** 场景 5 若跳过空位，Trina 与 Flora 相邻（始终满 HP），P2 必然触发，与实测不符。
